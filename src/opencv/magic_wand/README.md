# 마법 지팡이 (Magic Wand) — OpenCV 색상 추적 궤적 앱

빨간 펜 뚜껑 같은 **색깔 있는 물체**를 웹캠 앞에서 움직이면, 그 궤적이 화면에 마법처럼 그려집니다.
**딥러닝 없이 고전 CV 기법(HSV 마스킹 + 컨투어 무게중심)만** 사용합니다.

*(합성 데이터로 렌더한 실제 출력 — 웹캠 대신 코드로 만든 빨간 원이 사인 곡선을 따라 움직인 결과)*

## 실행

```bash
pip install -r requirements.txt
python magic_wand.py
```

| 키 | 동작 |
|---|---|
| `s` | 캔버스 지우기 |
| `c` | 추적 색상 변경 (RED → BLUE → GREEN → YELLOW 순환) |
| `q` | 종료 |

## 동작 원리

```
BGR 프레임 → cvtColor(HSV) → inRange(색상 범위) → 모폴로지(노이즈 제거)
          → findContours → 가장 큰 컨투어 → moments로 무게중심
          → 이전 좌표와 선으로 연결 → 캔버스에 누적
```

핵심 포인트 2가지:

1. **왜 HSV인가** — BGR에서 "빨강"은 조명이 바뀌면 세 채널이 전부 흔들립니다. HSV는 색상(H)·채도(S)·명도(V)가 분리돼 있어 조명 변화가 주로 V만 건드리므로, H 범위를 좁게 · V 범위를 넓게 잡으면 안정적으로 추적됩니다.
2. **OpenCV의 H는 0~179** — 표준 색상환 0~360°를 uint8에 담으려 절반으로 압축한 값입니다. 빨강은 0° 부근이라 **범위가 끊겨서 두 구간(0\~10, 170\~179)**이 필요합니다. `COLOR_PRESETS`의 `RED`만 `ranges`가 2개인 이유입니다.

## 조정 가능한 상수 (`magic_wand.py` 상단)

| 상수 | 기본값 | 의미 |
|---|---|---|
| `COLOR_PRESETS` | RED 외 3종 | 추적 색상의 HSV 범위. 조명이 어두우면 각 범위의 `V` 하한(70)을 낮추세요 |

### ✅ 검증한 것 — 합성 데이터 기반 수치 검증

웹캠이 없는 환경이라, numpy로 **정답 좌표를 아는** 색 원이 사인 곡선을 따라 움직이는 합성 프레임(640×480, 회색 배경 + 랜덤 노이즈)을 만들어 검증했습니다.

| 항목 | 결과 |
|---|---|
| **프레임별 무게중심 정확도** | 4개 색상 × 8프레임 = 32개 측정, **평균/최대 오차 0.000px** (목표 5px 이내) |
| **작은 동색 방해물 존재 시** | 가장 큰 컨투어 선택 → 오차 **0.000px** |
| **물체 없는 프레임** | `None` 반환 (오검출 없음) |
| **`MIN_AREA` 미만(r=5, 면적≈79)** | `None` 반환 (노이즈 무시 정상) |
| **궤적-경로 일치** | 캔버스에 그려진 선과 정답 경로 8점 사이 최단거리 **평균/최대 0.000px** |
| **페이드아웃** | 최대 픽셀값 255 → 5f 175 → 15f 80 → 30f 22 → **60f 0** (양수 구간 엄격 감소, 완전 소멸 확인) |
| **글로우** | 궤적에서 5px 떨어진 픽셀 `0 → 60`, 10px `0 → 39`, 20px `0 → 6` (빛 번짐 확인) |
| **전체 합성 렌더** | 26프레임 렌더 후 이미지 저장 → 시각 확인 완료 |

산출물: `output/verify_trail_path.png`, `verify_fade_{00,05,15,30,60}.png`, `verify_glow.png`, `verify_render_{05,12,25}.png`

검증 중 관찰된 사실 하나: 페이드는 uint8 정수 절삭 때문에 이론값(255×0.93ⁿ)보다 **약간 빠르게** 감쇠합니다(30프레임 시점 22 vs 이론 28.9). 부작용이 아니라 오히려 이득 — 잔상이 1~2 값에 영원히 남지 않고 **정확히 0으로 사라집니다.**

### ❌ 검증하지 못한 것

이 환경에는 웹캠이 없어 **실제 사용감은 전혀 검증되지 않았습니다.** 아래는 모두 미검증입니다.

- **실제 조명 환경의 HSV 범위 적합성** — 합성 프레임의 빨강은 순수한 `(0,0,255)`라 100% 검출됩니다. 실제 펜 뚜껑은 반사·그림자 때문에 S/V가 크게 흔들리므로, `COLOR_PRESETS`의 하한값(S 120, V 70) 조정이 필요할 수 있습니다.
- **모션 블러** — 빠르게 휘두르면 물체가 번지면서 채도가 떨어져 검출이 끊길 수 있습니다. 합성 프레임은 항상 선명합니다.
- **프레임레이트/체감 반응성** — 페이드 속도(`FADE=0.93`)와 무지개 진행 속도(`HUE_STEP=3`)는 "프레임당" 값이라, 실제 카메라 FPS에 따라 체감이 달라집니다. 30fps 기준으로 궤적은 약 2초간 남습니다.
- **배경 간섭** — 배경에 같은 색 물체(빨간 옷, 나무 책상)가 있으면 그쪽으로 추적이 튈 수 있습니다. `MAX_JUMP`가 완화하지만 근본 해결책은 아닙니다.
- **`cv2.VideoCapture` / `imshow` 동작** — 카메라 열기, 창 표시, 키 입력 루프는 실행해 보지 못했습니다. 추적·연출 로직만 함수 단위로 검증했습니다.

**즉, "코드가 도는가"는 검증됐고 "실제로 쓸 만한가"는 미검증입니다.** 웹캠이 있는 환경에서 한 번 돌려본 뒤 위 상수들을 조정하는 단계가 남아 있습니다.
