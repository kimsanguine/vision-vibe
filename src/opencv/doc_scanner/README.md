# OpenCV 문서 스캐너 (딥러닝 없음)

종이·영수증 사진에서 종이의 네 모서리를 자동으로 찾아 원근 보정해 반듯하게 펴주는 CamScanner 스타일 스크립트입니다.
Part2(번호판 인식)에서 쓴 원근 보정을 문서 전체로 확장한 과제이며, **OpenCV 고전 기법만** 사용합니다.

## 실행법

```bash
cd 260728_vision_vibe_workshop/src/opencv/doc_scanner

# 1. 검증용 합성 이미지 생성 (실제 문서 사진이 없으므로)
python3 make_test_images.py

# 2. 스캔 실행
python3 scan.py samples/case_b_strong_perspective.jpg

# 3. 정답 대비 수치 채점
python3 verify.py
```

의존성: `opencv-python`, `numpy`, `pillow` (검증 환경: cv2 4.13.0 / numpy 2.5.0 / PIL 12.2.0, macOS)

### CLI 옵션

| 옵션 | 설명 |
|---|---|
| `input` | 입력 이미지 경로 (필수) |
| `-o, --output` | 보정 결과 저장 경로 (기본: `output/<이름>_scanned.jpg`) |
| `--viz` | 단계별 시각화 저장 경로 (기본: `output/<이름>_viz.jpg`) |
| `--strict` | 4각형 검출 실패 시 폴백 없이 에러로 종료 |

### 종료 코드

| 코드 | 의미 |
|---|---|
| 0 | 문서 검출 + 보정 성공 |
| 1 | 이미지를 읽을 수 없음 |
| 2 | `--strict` 모드에서 4각형 검출 실패 |
| 3 | 4각형 검출 실패 → 폴백(원본 그대로 출력)으로 처리됨 |

## 파이프라인

```
그레이스케일 → 가우시안 블러 → Canny 엣지 → findContours
  → 면적 최대 4각형 approxPolyDP → 꼭짓점 정렬 → 종횡비 복원
  → getPerspectiveTransform → warpPerspective
```

설계상 짚어둘 점 세 가지입니다.

**1. 엣지 검출은 축소본(가로 600px)에서, 보정은 원본 해상도에서.**
속도와 노이즈 억제를 위해 축소본에서 꼭짓점을 찾고, 찾은 좌표를 원본 스케일로 되돌려 원본 화질로 보정합니다.
Canny 임계값은 밝기 중앙값 기준으로 자동 산출합니다(고정 임계값은 조명이 바뀌면 쉽게 깨집니다).
엣지가 조명 때문에 끊겨 contour가 닫히지 않는 걸 막으려고 한 번 팽창시킵니다.

**2. 꼭짓점 순서 정렬이 필수입니다.**
`findContours`가 주는 4점은 순서가 보장되지 않아, 정렬 없이 `getPerspectiveTransform`에 넣으면
결과가 뒤집히거나 대각으로 꼬입니다. `x+y` 최소/최대 → TL/BR, `y-x` 최소/최대 → TR/BL로 정렬합니다.

**3. 종횡비는 소실점으로 복원합니다.**
널리 쓰이는 "마주보는 두 변 중 긴 쪽을 채택" 휴리스틱은 원근이 강하면 크게 틀립니다.
카메라에 가까운 변이 실제보다 길게 찍히기 때문입니다 — 아래 검증에서 **오차 50.78%** 로 확인됐습니다.

대신 마주보는 변 두 쌍을 각각 연장해 소실점 2개를 구합니다. 이 두 소실점이 가리키는 방향은
3D 공간에서 서로 직교하므로, 그 직교 조건이 카메라 초점거리 `f`에 대한 방정식을 하나 줍니다.

```
f² = -[(x₁-u₀)(x₂-u₀) + (y₁-v₀)(y₂-v₀)]     (u₀,v₀) = 이미지 중심
```

`f`를 알면 단위 정사각형→4각형 호모그래피의 두 열을 카메라 좌표계로 되돌려 실제 종횡비를 얻습니다
(Zhang & He, *Whiteboard scanning and image enhancement*, 2006). 딥러닝 없이 순수 기하학입니다.

추정이 불안정한 경우 — 변이 거의 평행(정면 촬영), 소실점이 대각선의 50배보다 멀리 있음, `f² ≤ 0`,
복원된 비율이 0.05~20 범위 밖 — 에는 `None`을 반환해 기존 휴리스틱으로 되돌아갑니다.
정면 촬영은 애초에 휴리스틱이 거의 정확한 구간이라 손해가 없습니다.

## 검출 실패 시 동작

조용히 이상한 결과를 내지 않습니다. 두 가지 모드가 있습니다.

- **기본(폴백)**: 이미지 전체를 문서로 간주해 **원근 보정 없이 원본을 그대로** 출력합니다.
  `[경고]` 메시지를 출력하고, 시각화 3번 패널 라벨이 `3. FALLBACK (보정 안 함)`으로 바뀌며, 종료 코드 3을 반환합니다.
- **`--strict`**: 폴백 없이 `[에러]` 메시지와 종료 코드 2로 중단합니다.

4각형 후보는 (a) 전체 면적의 15% 이상, (b) 볼록(convex), (c) `approxPolyDP` 결과가 정확히 4점
세 조건을 모두 만족해야 채택됩니다. 로고나 표 같은 작은 사각형이 문서로 오인되는 걸 막습니다.

또한 꼭짓점 정렬 결과에 같은 점이 두 번 배정되면(45° 이상 회전 등) 조용히 넘기지 않고 예외를 던집니다.

## 검증 상태

**실제 문서 사진은 없습니다.** PIL로 종이(흰 배경 + 검은 텍스트 줄)를 그린 뒤,
카메라 기울임을 3D로 시뮬레이션해 배경 위에 원근 투영으로 합성한 이미지로 검증했습니다.

임의로 사다리꼴 네 점을 찍지 않고 실제 핀홀 투영을 계산한 이유는, 그래야 "원래 종횡비"가 정의되어
채점이 가능하기 때문입니다. 주점(principal point)은 실제 카메라와 같도록 이미지 중심에 고정했습니다.
정답 꼭짓점 좌표는 `samples/ground_truth.json`에 저장됩니다.

### 결과 (`python3 verify.py`)

정답 종이 종횡비 = 620/877 = **0.7070** (A4 근사)

| 케이스 | 검출 | 꼭짓점 오차(평균) | 대각선 대비 | 복원 종횡비 | 종횡비 오차 | 휴리스틱만 썼을 때 | 판정 |
|---|---|---|---|---|---|---|---|
| (a) 살짝 기울어짐 | O | 1.31px | 0.080% | 0.7081 | **0.16%** | 1.73% | PASS |
| (b) 원근 심한 사다리꼴 | O | 1.99px | 0.121% | 0.6988 | **1.16%** | 50.78% | PASS |

- 합격 기준(이 프로젝트 자체 기준선, 업계 표준 아님): 꼭짓점 오차 ≤ 대각선의 1%, 종횡비 오차 ≤ 10%
- (b)는 상단 변이 하단 변보다 1.53배 넓은 강한 원근입니다.
- **소실점 보정의 효과**: (b)에서 종횡비 오차 50.78% → 1.16%. 휴리스틱만 쓰면 결과물이 옆으로 퍼집니다.
- 고정 시드를 써서 3회 반복 실행 결과가 소수점까지 동일함을 확인했습니다.

### 실패 경로도 실행해 확인했습니다

| 상황 | 결과 |

## 검증되지 않은 것 (중요)

위 수치는 **합성 이미지에 대한 것이며, 실제 스마트폰 사진 성능이 아닙니다.**
합성 이미지가 실제 사진보다 쉬운 지점을 구체적으로 적으면 다음과 같습니다.

- **배경이 단순합니다.** 매끈한 그라데이션 + 약한 노이즈뿐이라 종이 경계가 Canny에서 거의 항상 깨끗하게 잡힙니다.
  실제 책상에는 나뭇결·다른 서류·키보드·케이블이 있어 문서보다 큰 엣지 덩어리가 자주 생깁니다.
- **종이가 완전한 평면입니다.** 실제 영수증·구겨진 종이는 휘어 있어 변이 직선이 아니고,
  `approxPolyDP`가 4점이 아닌 5~7점을 내놓기 쉽습니다.
- **조명이 균일하고 그림자가 단순합니다.** 실제 사진의 국소 반사·손그림자·형광등 줄무늬는 넣지 않았습니다.
- **초점이 완벽하고 렌즈 왜곡이 없습니다.** 모션 블러, 얕은 심도, 광각 배럴 왜곡이 없습니다.
  특히 **렌즈 왜곡은 소실점 기반 종횡비 복원의 정확도를 직접 떨어뜨립니다** — 직선이 휘면 소실점 위치가 틀어집니다.
- **주점이 정확히 이미지 중심입니다.** 종횡비 복원은 이 가정 위에 서 있습니다.
  실제 카메라는 대체로 중심에 가깝지만 정확히 일치하지는 않고, 사진을 크롭하면 어긋납니다.
- **JPEG 압축 품질이 92로 높습니다.** 저조도에서 찍은 실제 사진의 압축 아티팩트·센서 노이즈는 반영되지 않았습니다.

또한 다음은 **아예 테스트하지 않았습니다**: 문서 모서리가 화면 밖으로 잘린 사진, 어두운 배경 위 어두운 종이,
흰 책상 위 흰 종이(대비 없음), 한 장면에 문서가 여러 장, 흑백이 아닌 컬러 문서 배경.

실제 사진에서의 성능을 알려면 실제 촬영본으로 다시 채점해야 합니다.

## 파일 구조

```
opencv/doc_scanner/
├── scan.py               # 메인 파이프라인 + CLI
├── make_test_images.py   # 합성 검증 이미지 생성 (PIL + 3D 투영)
├── verify.py             # 정답 대비 수치 채점
├── samples/              # 생성된 합성 이미지 + ground_truth.json
└── output/               # 보정 결과, 단계별 시각화, verify_report.json
```

`samples/`와 `output/`은 스크립트가 생성하므로 저장소에 커밋할 필요가 없습니다.
