# 웹캠 검증 체크리스트

이 저장소에서 **실제 웹캠으로 손이 검출되는지는 아직 아무도 확인하지 못했습니다.**
카메라 권한은 사람이 직접 승인해야 하고, 화면에 잡힌 손이 "내가 든 그 손"인지는
카메라를 켤 수 없는 쪽에서 판정할 방법이 없기 때문입니다.

그래서 마지막 관문은 사람이 넘어야 합니다. 아래 순서대로 따라가면 됩니다.
각 항목은 **화면에 실제로 뜨는 문장**을 기준으로 판단하세요.

소요 시간: 약 5분.

## 3. 미러링 / 엄지 부호 판정 ← **이 문서의 핵심**

### 왜 이걸 확인하나

`app.py:116` 은 `cv2.flip(frame, 1)` 로 좌우를 뒤집은 프레임을 판정에 넘깁니다.
그런데 `hand_lite/gesture.py:36-39` 에는 이렇게 적혀 있습니다.

> 카메라 입력이 좌우 미러링되지 **않았다고 가정**하면 (...)
> 이 가정이 깨지는 경우(셀피 모드 미러링 등)는 이 함수 밖에서 보정해야 한다.

그런데 `app.py` 어디에도 그 보정이 없습니다. **엄지 판정 부호가 뒤집혔을 가능성**이
남아 있고, 손 없이는 확정할 수 없습니다.
(설치된 `mediapipe 1.0.0` 패키지 문서에도 미러링 관련 서술이 없어 문서로는 못 풉니다 —
`grep -ri mirror` 로 확인했으며 무관한 TFLite 연산자 이름만 나옵니다.)

### 무엇을 보면 답이 나오나

`classify()` 에서 **바위는 엄지를 포함한 5개가 전부 '굽음'** 이어야 성립합니다.
따라서 엄지 부호가 뒤집혔다면:

> **주먹을 쥐었는데 `바위`가 아니라 `판정불가`가 나옵니다.**

좌표계를 이해할 필요 없이 이 한 줄만 보면 됩니다.
(합성 랜드마크로 실제 `classify()` 를 돌려 확인한 동작입니다.)

### 절차

2번에서 이어서 진행됩니다. 진단 도구가 세 가지 자세를 차례로 요청합니다.

> **중요: 손바닥이 카메라를 향하게 하세요.** 손등이 아닙니다. 가위바위보 낼 때 자세입니다.

- [ ] **① 오른손 보** — 오른손 손바닥을 활짝 펴서 카메라를 향해 든다 → Enter → 3초 카운트다운
- [ ] **② 오른손 바위** — 오른손 주먹을 쥐고 엄지를 손가락 위에 얹는다 → Enter
- [ ] **③ 왼손 보** — 왼손 손바닥을 활짝 펴서 카메라를 향해 든다 → Enter

각 자세마다 이런 두 줄이 찍힙니다.

```
    거울(app.py 경로)      handedness=Right 엄지폄=100%  제스처=보    (tip.x-ip.x=+0.041, 30프레임)
    원본(뒤집지 않음)      handedness=Left  엄지폄=100%  제스처=보    (tip.x-ip.x=-0.041, 30프레임)
```

같은 순간의 프레임을 **뒤집은 것 / 안 뒤집은 것** 두 갈래로 각각 추론한 결과입니다.
`app.py` 는 위쪽(거울) 경로만 씁니다. 아래쪽은 "뒤집기가 판정을 바꾸는가"를 보기 위한 대조군입니다.

마지막에 `판정` 블록이 나옵니다.

- [ ] 판정 블록의 마지막 줄이 `[통과]` 인지 `[실패]` 인지 확인했다

## 4. 결과별 다음 행동

### 결과 A — `[통과] 판정: ... 정상 동작합니다`

`app.py` 의 거울 모드와 `gesture.py` 조합은 **손바닥이 카메라를 향한 자세 범위에서**
문제가 없습니다. 의혹은 해소된 것으로 처리하고, `gesture.py:36-39` 주석이 오해를 부르므로
"뒤집힌 입력에서도 성립하는 이유"로 다시 쓸지 팀에 제안하세요.

### 결과 B — `[실패] 주먹을 쥐었는데 엄지가 '폄'으로 판정됩니다`

**엄지 부호 반전 확정.** 세 자세 모두 `판정불가`로 나왔을 것입니다.
출력 전체를 복사해 공유하세요. 수정은 `gesture.py` 를 건드리는 대신
`app.py` 에서 보정하는 쪽이 안전합니다 — `gesture.py` 는 순수 함수이고
`--image` 모드(뒤집지 않은 입력)도 같은 함수를 쓰기 때문입니다.

### 결과 C — `[실패] ... handedness 라벨이 실제 손과 반대입니다` (제스처는 전부 정상)

라벨만 뒤집혔고 제스처 판정은 맞는 상태입니다. 가위바위보 동작에는 지장이 없지만
화면에 "Left/Right"를 표시하거나 손별로 다른 처리를 하려면 보정이 필요합니다.
이 결과도 그대로 공유하세요.

### 결과 D — `[실패] 어떤 자세에서도 손이 검출되지 않아 판정할 수 없습니다`

판정이 아니라 **측정 실패**입니다. 조명을 밝게 하고 손이 화면 중앙에 크게 잡히도록 한 뒤
`--hold 60` 으로 관측 프레임을 늘려 재실행하세요.

## 6. 참고 — 알려진 한계 (버그로 신고하지 않아도 되는 것)

`gesture.py` 가 스스로 명시한 한계입니다. 아래 상황의 오판정은 예상된 동작입니다.

- 손을 옆으로 눕히면 검지~소지 판정이 틀립니다 (`tip.y < pip.y` 규칙은 손이 세워진 자세를 전제)
- 손등을 카메라로 향하면 엄지 판정이 틀릴 수 있습니다
- 가위바위보 세 모양이 아닌 조합은 억지로 분류하지 않고 `판정불가` 로 둡니다

## 7. 아직 검증되지 않은 것 (정직하게)

이 문서와 `doctor.py` 를 만든 시점에 **실제로 실행해 확인한 것**은 여기까지입니다.

- ✅ 확인함: 1단계(환경 점검), 2단계(모델 로드 + 빈 프레임 추론) — 실제 실행 출력 확인
- ✅ 확인함: 4단계 프레임 판정 로직 — 가짜 검은/실패/정상 프레임으로 세 경로 모두 실행
- ✅ 확인함: 6단계 판정 로직 — 정상 / 엄지반전 / 라벨반전 / 미검출 4개 시나리오로 실행
- ❌ **미확인**: 실제 카메라를 여는 경로(3단계), 실제 손 검출(5단계), 실제 손을 이용한 미러링 판정(6단계)
- ❌ **미확인**: `app.py` 웹캠 모드가 실제로 동작하는지

마지막 두 줄이 이 체크리스트의 존재 이유입니다. 당신이 채워야 할 칸입니다.
