## 1. 문제

워크샵 `spec.md` Part 3의 목표는 **"웹캠 실시간 손 감지를 MediaPipe로 붙여보고
YOLO 방식과 비교"**다. 그런데 비교의 한쪽(`yolo/rps`, 가위바위보 YOLO 편)은
있는데, **같은 과제를 MediaPipe로 푼 짝이 없었다.**

기존 MediaPipe 자산은 성격이 달랐다.

| 자산 | 한계 |
|---|---|
| `mediapipe/webcam_tutorial/` | 손 랜드마크 렌더까지만. 제스처 판정 없음 → YOLO와 같은 과제가 아님 |
| `part3_flutter_web_a~d/` | Flutter Web + JS/WASM. 언어·런타임이 달라 Python YOLO 편과 직접 비교 불가 |

비교 대상이 과제도 언어도 다르면 **"학습된 모델이 언제 필요한가"라는 질문에
답할 수 없다.** 조건을 맞춘 짝이 필요했다.

### 페인 강도

| 근거 | 라벨 |
|---|---|
| `spec.md` Part 3이 "YOLO 방식과 비교"를 명시 | [사실] — 원문 인용 |
| `yolo/rps` 모델 실측 114.4 MB, 학습 데이터·파인튜닝 필요 | [사실] — `os.path.getsize` |
| 수강생이 "무거운 쪽만 보고 CV = 학습 필요"로 오해할 위험 | [추론] — 강사 판단 |

## 2. 사용자

- **1차**: 워크샵 수강생 — Claude Code 경험은 있으나 CV·딥러닝은 처음
- **2차**: 강사(김생근) — 강의장에서 시연하고 학생 질문에 답해야 함

사용자 ≠ 지불자 구조는 아니다(사내/자체 워크샵 자료).

강사 관점에서 중요한 것: **학생 앞에서 틀린 말을 하지 않는 것.**
"MediaPipe가 더 가볍다" 같은 주장이 반례로 무너지면 신뢰가 깨진다.

## 3. 해결 기능 (3개)

| # | 기능 | 근거 |
|---|---|---|
| F1 | **MediaPipe 손 추적 엔진** — 사전학습 `.task` 7.5MB, 학습 0회 | YOLO와의 대비축 |
| F2 | **가위바위보 제스처 판정** — 랜드마크 21점의 기하 규칙, 모델 없음 | `yolo/rps`와 동일 과제로 맞춤 |
| F3 | **경량성 벤치마크** — 용량·속도를 코드로 실측, 사실/추정 라벨 분리 | 강의 주장의 근거 확보 |
| F4 | **가위바위보 게임** — F2 위에 AI 대결·점수판·제스처 프레임 안정화(`rps_game.py`) | `yolo/rps`가 게임 형태이므로 짝을 맞춤. 후속 확장(당초 4기능 계획엔 없었음) |
| F5 | **웹캠 진단 도구**(`doctor.py`) — 카메라 열기 실패를 단계별로 구분해 원인 안내 | 강의장에서 첫 실행이 실패할 위험 대응. 후속 확장 |

F2에 학습된 분류기를 쓰지 않은 이유: **손가락이 펴졌는지는 좌표 비교로 답이
나오는 결정적 문제**다. 결정적 로직에 모델을 끼우지 않는다.

## 4. 범위 / 비범위

**범위**
- 웹캠 실시간 + 정지 이미지 두 경로
- 가위바위보 3종 + 판정불가(UNKNOWN)

**비범위**

- 가위바위보 외 제스처 확장
- 얼굴·사물 감지 — 이미 `part3_flutter_web_b/c`에 있음
- OpenCV 전통 영상처리(윤곽·Convexity Defects)로 푸는 세 번째 축 — **미착수**,
  3자 비교를 완성하려면 필요 (아래 8절)
- 모바일·웹 배포 — Flutter Web 버전이 담당
